# 성능 개선 기준

성능 작업이 요청되면 해당 실행 경로만 측정하고 수정한다. WPF·정적 사이트에 공통으로 적용하고, API 요청·DB 쿼리 기준은 그 기능이 있는 작업에서만 적용한다. 기존 [실행 경계](../CODING_STANDARDS.md#개인정보와-실행-경계)와 신규 의존성·운영 데이터 변경의 [승인 규칙](../CODING_STANDARDS.md#작업-순서와-승인)을 유지한다.

## 측정과 검증

- 같은 환경·데이터·화면 상태에서 변경 전 기준값을 기록한다. 체감 속도나 빌드 파일 크기 하나만으로 개선을 판단하지 않는다.
- 문제 경로의 렌더링·요청·쿼리 수, CPU·RAM, 지연, 실제 전송량 중 필요한 값만 수집한다. 외부 텔레메트리를 추가하는 근거로 사용하지 않는다.
- 관련 동작을 재현하고 필요한 최소 변경 후 같은 조건으로 비교한다. 기능·권한·접근성의 회귀도 확인한다.
- 결과에는 측정 조건·전후 값·검증한 범위만 기록한다. 다른 장치나 운영 환경에서의 효과를 추정해 완료로 보고하지 않는다.

## 개선 항목

| 항목 | 확인·수정 | 검증 |
|---|---|---|
| 1. 불필요한 렌더링 | 갱신 횟수와 원인을 먼저 확인한다. 바뀌지 않은 표시의 재생성, 중복 이벤트, 숨겨진 화면의 그리기·레이아웃을 줄인다. 시간 표시·차트 등 실제 변경과 필요한 감시는 유지한다. | 동일 동작의 갱신 횟수·프레임 지연·CPU와 숨김·복귀·키보드 동작 |
| 2. 지연 로딩 | 초기 화면에 필요 없는 UI·스크립트·이미지를 사용 시점에 로드한다. 불용 코드·의존성을 먼저 제거하고, 코드 분할은 측정된 초기 로딩 병목에 적용한다. | 최초 표시·전송량과 지연 기능 첫 사용·재사용·로딩 실패 |
| 3. 요청·캐시 | 중복 요청을 합치고 불필요해진 작업은 취소한다. 검색은 필요할 때 입력 지연을 적용하고 이전 응답이 최신 상태를 덮지 않게 한다. 캐시 키·유효 기간·무효화·오류 응답 정책을 명시한다. | 요청 수, 첫 요청·캐시 재사용·만료·쓰기 직후·응답 순서 역전 |
| 4. 느린 쿼리·N+1 | 실행 시간·계획·조회 행·호출 수로 병목을 찾는다. 필요한 필드와 제한된 행만 읽고 관계 조회는 적절한 집합·배치로 묶는다. 과도한 JOIN의 중복 행·전송량도 확인한다. | 대표 데이터에서 부모 항목 증가에 따른 쿼리 수·응답 크기·지연 |
| 5. 이미지·폰트·스크립트 | 표시 크기에 맞는 이미지·압축·크기 속성을 사용한다. 필요한 글꼴·두께·문자와 스크립트만 제공하고, 비필수 자산의 로딩을 늦춘다. | 모바일·고배율·한국어·대체 폰트, 첫 표시·전송량·레이아웃 이동 |

## 실행 환경별 기준

- **WPF:** UI 생성·레이아웃·바인딩과 실제 스캔 비용을 구분한다. PID·시작 시각·권한·종료 직전 검증은 캐시된 판단으로 대체하지 않는다. 앱 자원 비교는 [측정 기록과 명령](resource-usage.md#재측정)을 참고한다.
- **정적 사이트:** 첫 화면의 핵심 이미지·텍스트를 지연시키지 않는다. 코드 분할이 전체 코드 크기를 자동으로 줄인다고 가정하지 않고 초기 전송량과 전체 전송량을 구분한다. 폰트 최적화 후 필요한 문자·대체 표시와 라이선스를 유지한다.
- **캐시:** 권한·사용자·테넌트별 데이터를 섞지 않고 권한 변경·로그아웃·쓰기 후 무효화를 검증한다. 오래 보관할 정적 자산은 내용 변경 시 URL도 바꾸며, 변경되는 HTML·다운로드에 같은 정책을 무조건 적용하지 않는다. `no-cache`는 저장 금지가 아니라 재사용 전 재검증이다.
- **DB/API:** 프런트엔드 자산의 지연 로딩과 ORM 관계의 지연 조회를 구분한다. 후자는 N+1을 만들 수 있다. 빈 검색어·필터·권한·목록 상한은 [API 기준](api-design.md)을 유지하며 성능을 이유로 생략하지 않는다.
- **게시:** 로컬 서버의 캐시·압축 헤더가 실제 호스팅에 적용됐다고 가정하지 않는다. 사이트 동작은 [게시 안내](publishing.md#준비검증)의 해당 검사로 확인한다.

WPF는 [Microsoft 성능 안내](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/performance), 웹 자산은 [MDN 지연 로딩](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Lazy_loading)과 [HTTP 캐시](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching), 쿼리는 [효율적인 관계 조회와 N+1](https://learn.microsoft.com/en-us/ef/core/performance/efficient-querying)을 참고한다. 참고 문서는 프레임워크·패키지 추가를 요구하지 않는다.
